# 문제 해결

아래는 실제로 많이 헷갈리는 증상 기준으로 정리한 빠른 확인표입니다.

지원 이슈 등록:

- GitHub Issues: <https://github.com/Cheol-H-Jeong/eoditdeora/issues>

## 검색창에 타이핑해도 결과가 안 나옵니다

아래 순서대로 확인해 주세요.

1. 앱을 처음 켠 직후라면 아직 색인 중일 수 있습니다.
2. 우측 사이드바 `감시 폴더`에 검색할 폴더가 실제로 등록되어 있는지 확인해 주세요.
3. `문서 본문 색인` 카운트와 `파일명 색인` 카운트가 늘어나는지 확인해 주세요.
4. 문서 확장자가 `색인 대상 확장자` 목록에 포함되어 있는지 확인해 주세요.
5. 새로 추가한 확장자라면 `재탐색`을 한 번 실행해 주세요.

참고:

- 파일명 검색은 보통 먼저 보입니다.
- 본문 검색은 초기 색인이 끝나야 안정적으로 나옵니다.

## API 연결 오류가 뜹니다

아래 항목을 확인해 주세요.

1. `API key`가 필요한 서버라면 값이 비어 있지 않은지 확인해 주세요.
2. 브라우저나 터미널에서 엔드포인트가 실제로 열리는지 확인해 주세요.
3. 주소 끝의 `/v1` 포함 여부가 서버 종류와 맞는지 확인해 주세요.
4. 앱에서 `테스트`를 누른 뒤 상태가 바뀌는지 확인해 주세요.

상태 LED는 아래처럼 해석하시면 됩니다.

- 초록색: `LLM`과 `임베딩`이 모두 연결된 상태입니다.
- 노란색: 일부 역할만 연결된 상태입니다.
- 빨간색: 아직 설정되지 않았거나, 연결 테스트에 실패한 상태입니다.

연결 확인 예시:

```bash
curl http://127.0.0.1:8081/v1/models
```

Bearer 인증이 필요한 경우:

```bash
curl -H "Authorization: Bearer YOUR_BEARER_KEY_HERE" http://127.0.0.1:8081/v1/models
```

## 앱이 열리자마자 꺼집니다

먼저 로그 파일을 확인해 주세요.

Windows 로그 경로:

```text
%LOCALAPPDATA%\eoditdeora\eoditdeora\Logs\eoditdeora.log
```

위 경로를 파일 탐색기 주소창에 그대로 붙여 넣어 열어 보신 뒤, 가장 마지막 오류 줄을 확인해 주세요.

이슈를 등록하실 때는 아래 정보를 함께 적어 주세요.

1. 사용 중인 Windows 버전 또는 Linux 배포판
2. 설치 파일 이름
3. 앱이 꺼지기 직전 화면에서 하신 작업
4. `eoditdeora.log` 마지막 30줄 정도

이슈 등록:

- <https://github.com/Cheol-H-Jeong/eoditdeora/issues>

## AI 답변이 비어있습니다

이 경우는 검색이 실패했다기보다, 연결한 LLM이 답변 본문 대신 reasoning 정보만 내보내는 설정일 가능성이 큽니다.

확인할 점:

1. 현재 연결한 모델이 일반 채팅 응답을 실제 `content` 필드로 내보내는지 확인해 주세요.
2. reasoning 전용 또는 체인오브소트만 노출하는 서버 설정은 아닌지 확인해 주세요.
3. 같은 엔드포인트에 일반적인 채팅 모델을 연결했을 때 답변이 나오는지 비교해 주세요.

가능하면 답변용 LLM에는 일반 텍스트 응답을 안정적으로 반환하는 OpenAI 호환 모델을 지정해 주세요.

## 엔드포인트 설정 입력창이 자꾸 초기화됩니다

이 문제는 `v0.1.3` 이상에서 수정되었습니다.

확인 순서:

1. 현재 설치한 버전을 확인해 주세요.
2. `v0.1.3` 미만이라면 최신 설치 파일로 업데이트해 주세요.
3. 업데이트 후에도 반복되면 Issues에 재현 절차를 남겨 주세요.

## 그래도 해결되지 않으면

아래 항목을 함께 적어 주시면 확인이 빨라집니다.

1. 운영체제와 버전
2. 앱 버전
3. 사용 중인 LLM 서버 종류
4. LLM, 임베딩, 리랭커 각각의 주소
5. 재현 순서
6. 로그 파일 일부
